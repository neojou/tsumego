# 決策樹顯示

Glossary：`CONTEXT.md`。契約：`docs/adr/0011`、`0012`、`0015`、`0019`、`0023`、`0026`。對照地圖：`docs/decision.md`（已寫，本規格不重做）。

## Problem Statement

解題者在白思考時，右邊是平鋪編號的搜尋路徑（`1. 白下 B3 -> 黑下 A3 -> 結果 成功`），同一手白散在各處，每條終局都整行列出。之後要研究怎麼搜得更快，需要先看清「前兩步試過哪些、第三步起程式認為最頑強的是哪一條」。現在的列表不像決策，也把成功／失敗和對局結算混在同一套字。

## Solution

右邊欄改成 **決策樹**（ADR-0026）。解題器仍不限時、每走到終局仍報一條 **搜尋路徑**（ADR-0019）。殼把這些結果投影成三層樹：白第一手、黑第二手列出出現過的所有；第三步起每個（白、黑）只露出該白節點 **最長抵抗** 的續線直到終局。已出現的（白、黑）只改寫續線、不搬家。葉子寫 **黑勝** 或 **白勝**。對局仍是成功／失敗。不編號。搜尋範圍與應手不變。

## User Stories

1. As a 解題者, I want 右邊欄標題是「決策樹」, so that 看的是搜尋怎麼分支，不是預錄解答。
2. As a 解題者, I want 決策樹預設打開、紙墨窄欄、可捲動, so that 思考中仍看得到算過什麼，又不像卡片遊戲。
3. As a 解題者, I want 白第一手列出搜尋裡出現過的所有白棋著手, so that 看得出程式試了哪些抵抗。
4. As a 解題者, I want 每個白第一手底下列出出現過的所有黑第二手, so that 看得出黑試了哪些強迫。
5. As a 解題者, I want 每個（白第一手、黑第二手）底下只看到一條從白第三手起到終局的續線, so that 第三步之後是最長抵抗，不是所有終局平鋪。
6. As a 解題者, I want 那條續線含續上的黑與白直到黑勝或白勝, so that 看得出這一枝怎麼收。
7. As a 解題者, I want 續線上的白第三手是該節點的最長抵抗, so that 和盤上應手用同一套「強」。
8. As a 解題者, I want 不同黑第二手可以對應不同的白第三手, so that 每個黑試之後白都有自己的最長抵抗。
9. As a 解題者, I want 白區塊依該白第一手第一次出現的順序排, so that 已看到的列不會因座標重排而跳走。
10. As a 解題者, I want 新的黑第二手加在該白底下最後, so that 同一手白仍放在一起。
11. As a 解題者, I want 新的白第一手加在樹最底, so that 新區塊不插進已看過的白中間。
12. As a 解題者, I want 已出現的（白、黑）在最長抵抗被取代時只改寫第三層那一行, so that 同列更新、不另開一行、也不搬家。
13. As a 解題者, I want 決策樹列不帶 `1.` `2.` 編號, so that 縮排樹不會再像平鋪清單。
14. As a 解題者, I want 三層縮排：白第一手、其下黑第二手、其下整條續線, so that 前兩步是「全部」、第三步起是一條線。
15. As a 解題者, I want 每一枝結尾是「黑勝」或「白勝」, so that 這一枝黑能不能強迫題型過，一眼分得清。
16. As a 解題者, I want 黑勝表示這一枝黑能強迫過、白勝表示不能, so that 殺棋裡黑勝對得上目標死、白勝對得上強迫失敗。
17. As a 解題者, I want 對局結算仍顯示成功或失敗, so that 這題過不過和決策樹葉子不是同一個詞。
18. As a 解題者, I want 思考中仍看到「搜尋路徑數目： N」或「搜尋路徑數目： N（列出 M）」, so that 知道實際走完多少條、畫面列了多少葉子。
19. As a 解題者, I want N 是實際走完的搜尋路徑條數、不封頂, so that 之後研究加速時看得到真實搜尋量。
20. As a 解題者, I want M 是畫面上的（白、黑）葉子數、最多 1000, so that 極端題不會把欄撐爆。
21. As a 解題者, I want 超過 1000 個（白、黑）時總數仍增加、不再長新葉子, so that 數目誠實、畫面有上限。
22. As a 解題者, I want 走完的搜尋路徑若與已列葉子重複，總數仍加、不另開列, so that 同一（白、黑）只有一行。
23. As a 解題者, I want 白思考時決策樹隨終局一條條長出來, so that 不必等全部搜完才看到前兩步。
24. As a 解題者, I want 一有該（白、黑）的路徑就把第三層寫上當時的最長抵抗續線, so that 不必等證明結束才收束。
25. As a 解題者, I want 迭代加深後更頑強的續線出現時，同一葉子改寫成新續線, so that 深度 1 的 C 可以被深度 5 的 C 取代而不跳行。
26. As a 解題者, I want 證明完成、尚未落應手時仍看到「從路徑中思考最強應手...」, so that 知道接下來是盤上那手，不是改樹標題。
27. As a 解題者, I want 應手或反駁手落下後決策樹仍留在欄裡, so that 結算後還能回看剛算過什麼。
28. As a 解題者, I want 悔棋後決策樹清空, so that 撤銷一對後不留下一手的樹。
29. As a 解題者, I want 重做後先不列出決策樹, so that 和重做契約一致。
30. As a 解題者, I want 重做後再下同一手時決策樹直接重現、不必重算, so that 快取的搜尋結果仍能顯示。
31. As a 解題者, I want 決策樹不列白停／黑停, so that 搜尋加速用的停不會出現在樹上。
32. As a 解題者, I want 我按停仍可用, so that 使用者停和搜尋不報停是兩件事。
33. As a 解題者, I want 脫先被做活點反駁時決策樹仍能顯示那一枝白勝, so that 早退的反駁也看得到。
34. As a 解題者, I want File → Samples 的 15K／13K／8K 殺棋同一手仍是同一應手, so that 顯示收束不改最長抵抗。
35. As a 解題者, I want Desktop 與 Wasm 同一棵決策樹, so that 兩邊對照學習時長得一樣。
36. As a 解題者, I want 輪白思考時間與「目前動作」仍在, so that 決策樹只換右邊欄，不拆左上狀態。
37. As a 解題者, I want 決策樹與對局左上用同一套字級, so that 殼沒有忽大忽小。
38. As a 解題者, I want 新路徑讓樹變長時仍捲到看得到最新那塊, so that 長搜尋時不必自己找最後一列。
39. As a 解題者, I want 空對局、尚未落子時右邊沒有一棵舊樹, so that 換題或重做不會髒掉。
40. As a 解題者, I want 思考中悔棋或停會中止搜尋並依對局規則更新樹或盤, so that 決策樹不在已取消的搜尋上繼續改寫。
41. As a 解題者, I want 不把右邊叫成解答樹或正解變化, so that 不會以為只有一解。
42. As a 之後改搜尋的人, I want `docs/decision.md` 仍是現況對照地圖, so that 改 df-pn／FTL／模式表前對得回程式，不必從平鋪列表猜算法。
43. As a 之後改搜尋的人, I want 決策樹收束不剪 canForce 要走的枝, so that 研究加速時不會把「少顯示」誤當成「少搜尋」。
44. As a 之後改搜尋的人, I want 走完條數 N 仍是 onPath 實際次數, so that 可以拿 N 當搜尋量基線。
45. As a 解題者, I want 第一層寫「白下 A1」、第二層「黑下 B11」、第三層「白下 C -> 黑下 D -> 黑勝」, so that 座標與誰下棋仍用題目盤標號。
46. As a 解題者, I want 只有白第一手、還沒有黑第二手的不完整枝不要單獨成列, so that 樹上每一葉子都對應至少一步白、一步黑（或該終局本來就在白第一手立刻分勝負時見下一條）。
47. As a 解題者, I want 白第一手立刻終局（沒有黑第二手）時，該白底下用一條續線／葉子表達黑勝或白勝, so that 短抵抗也看得到。
48. As a 解題者, I want 成功／失敗列的按鈕（重做、悔棋）不變, so that 只改樹，不改對局操作。
49. As a 解題者, I want 非法手仍不觸發搜尋、也就不長決策樹, so that 被拒的手不像有在算。
50. As a 解題者, I want 同一題連下兩手時，第二手的樹從空手長起（一手一樹）, so that 不會把上一手的（白、黑）區塊留在這一手。

## Implementation Decisions

- 只改解題模組對外報路徑的形狀，以及殼怎麼投影。規則、分類、最長抵抗的鍵、相關區、迭代加深 AND–OR、應手／反駁手落地不變。Desktop 與 Wasm 同一套。
- 解題器仍每走到終局報一條搜尋路徑（計入走完條數）。另外對每個（白第一手、黑第二手）維持目前最長抵抗續線（從第三手到終局＋黑勝／白勝），讓殼能同列改寫。不在殼上重算最長抵抗。
- 搜尋仍走完該走的枝；顯示收束不是空手、不是必應區、不是少展開白第三手。
- 搜尋路徑結尾與決策樹葉子用黑勝／白勝（黑能強迫過／不能）。對局狀態、按鈕旁仍成功／失敗。
- 決策樹視圖：白第一手區塊依第一次出現；新黑掛在該白最後；新白掛在樹最底。已有（白、黑）只替換第三層字串。不編號。
- 白第一手立刻終局：該白下一層就是那條結果，不必虛構黑第二手。
- 含停的路徑仍不報、不上樹。
- 走完條數不封頂。畫面最多 1000 個（白、黑）葉子（加上「白立刻終局」的葉子）；超出只加總數。
- 重做：畫面先空；同一局面再下同一手重用快取並顯示當時的決策樹。悔棋清樹並中止搜尋。
- 左上「目前動作」「搜尋路徑數目」「從路徑中思考最強應手...」文案保留。欄標題改「決策樹」。
- `docs/decision.md` 已存在；本規格實作時更新其中「殼未改」的句子，不重寫算法地圖。
- 既有平鋪編號契約（v0.2 故事裡的 `1. 白下 B3 -> …`）由 ADR-0026 取代。

投影狀態（決策，不是示範程式）大致是：

- 走完條數
- 白第一手的出現序
- 每個白底下黑第二手的出現序
- 每個（白、黑）目前的續線與黑勝／白勝
- 葉子列數上限 1000

## Testing Decisions

- 好測試只打外部行為：樹上看到什麼、數目、應手仍是哪一點。不測 Canvas 縮排像素、不測 HashMap、不把 canForce 的遞迴當 seam。
- **主 seam：決策樹投影。** 輸入是「終局搜尋路徑」與「（白、黑）最長抵抗續線更新」這類事件；輸出是三層樹＋走完條數＋列出葉子數。在此鎖定：第一次出現順序、同列改寫、新黑掛該白最後、新白掛最底、1000 葉子上限、不編號、黑勝／白勝、不列停、白立刻終局。這是新的、也是唯一要新開的 seam；放在對局／殼文案這一層，不要開第二套解題器測試。
- **既有解題 seam 必須繼續過：** 最長抵抗應手（例如 small_trick 黑 S19 後 R19、8K 黑 S18 後 T18）、反駁手做活點、路徑不列停、證明完成才 `pickingReply`、重做快取。顯示改變後，同一題同一手仍是同一應手。
- **數目 seam：** 既有「總數可超過列出條數」的契約保留；列出改為葉子數，總數仍是走完的搜尋路徑。
- Prior art：`PlayCopyTest`（數目標籤、曾測編號）、`SessionSolverTest`（路徑串流、停、cap、應手）、`SessionRulesTest`（重做清顯示）、`SmallTrickSolverTest`／`Kill8BugLoopTest`（應手穩定性）。編號測試改為「決策樹不編號」；路徑字串結尾從成功／失敗改為黑勝／白勝。
- 不斷言 df-pn／FTL／模式表；那些是 `docs/decision.md` 的「v1 沒有」，本規格不實作。

## Out of Scope

- 換搜尋引擎、剪第三步以後的搜尋、FTL、df-pn、EWS、專門化 MCTS、把區形模式表接入 canForce。
- 改最長抵抗的鍵、改相關區、改分類、改題型（仍只出殺棋）。
- 把右邊叫解答樹；把對局成功／失敗改成白勝／黑勝。
- 可摺疊樹節點、每手一層的深樹、給白 A 編號。
- 重做 `docs/decision.md` 的算法地圖（已有）；本規格只在殼落地後改「尚未改殼」那一句。
- Android／iOS。

## Further Notes

- 建議實作順序：路徑結尾黑勝／白勝 → 投影 seam 與測試（順序、改寫、cap）→ Session 串流接到投影 → 殼三層縮排與標題 → 確認既有應手測試仍過。
- 主 seam 若與預期不符，先改規格再動殼；不要在 Compose 裡用字串 `startsWith` 猜最長抵抗。
