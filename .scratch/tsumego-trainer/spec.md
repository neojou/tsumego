# 詰碁訓練機

Glossary：`CONTEXT.md`。契約：`docs/adr/0001`–`0023`（`0006` 已被 `0018` 取代；`0005`、`0016` 已被 `0019` 取代；`0021` 的 tenuki 探反駁已被 `0022` 取代）。

## Problem Statement

我想用 Desktop 和瀏覽器練圍棋死活，從棋譜圖匯入題目，自己在盤上下黑。程式要像對手一樣抵抗，而不是播放預錄解答；走錯要看得出為什麼輸，走對任何能達成目標的變化都該過。現在 repo 只是一個 KMP 空殼（About 與佔位文字），沒有題目盤、沒有對局、沒有解題。

## Solution

做一個 **詰碁訓練機**：題目一律 **黑先**，五種 **題型**（做活、殺棋、雙活題、劫活、劫殺），在裁切的 **題目盤** 上對 **目標棋串** 判定。使用者執黑；程式用同一套解題器下 **應手** 或 **反駁手**。可從對齊的 **棋譜圖** 走進 **確認畫面** 再存成 **題目檔**，也可直接開既有題目檔。v1 跑在 Desktop 與 Wasm，棋盤用 Compose Canvas 畫出帶光影的棋子。

## User Stories

1. As a 解題者, I want 打開內建樣例題目, so that 不必先匯入就能開始練。
2. As a 解題者, I want 從題目檔開啟一道題, so that Desktop 做好的題可以拿到 Wasm 繼續解。
3. As a 解題者, I want 把目前的題目存成題目檔, so that 下次或另一個平台能再開。
4. As a 解題者, I want 看到裁切後的題目盤而不是空的十九路, so that 不會誤以為可以往圖外逃跑。
5. As a 解題者, I want 真盤邊的氣比中腹少、牆不可下也不給氣, so that 角題與邊題的氣數與書上一致。
6. As a 解題者, I want 棋盤座標顯示為 A–T（跳 I）與 1–19、A1 在左下, so that 與棋譜圖上的標號對得起來。
7. As a 解題者, I want 棋子看起來有立體光影（木紋、高光、落影）且隨交叉點間距縮放, so that 盤面接近真實棋盤而不是扁平圓點。
8. As a 解題者, I want 點交叉點落下黑子, so that 用滑鼠或觸控就能著手。
9. As a 解題者, I want 點在已有子的點或牆上時被拒絕且不算一手, so that 不會弄亂對局。
10. As a 解題者, I want 真自殺被拒絕且不算一手, so that 不會下出無氣自盡。
11. As a 解題者, I want 倒撲合法, so that 死活裡常見的撲才能下。
12. As a 解題者, I want 落下後提掉無氣的對方棋串, so that 吃子與死活進行一致。
13. As a 解題者, I want 同型反覆被禁, so that 單劫立即回提與長循環都不會發生。
14. As a 解題者, I want 我下完後程式自動下應手, so that 白棋在抵抗而不是等我替兩邊下。
15. As a 解題者, I want 任何仍能達成該題型的著手都過, so that 這是訓練機而不是唯一正解測驗。
16. As a 解題者, I want 程式在我仍能強迫成功時下最長抵抗, so that 每次同一局面的應手固定且最難收掉。
17. As a 解題者, I want Desktop 與 Wasm 對同一手給出同一應手, so that 兩邊行為一致。
18. As a 解題者, I want 做活題在目標棋串無條件活時宣告成功, so that 做成兩眼／Benson 活就結束。
19. As a 解題者, I want 做活題在雙活、劫活或死時不算成功, so that 題型不會被較弱的活混過去。
20. As a 解題者, I want 殺棋題在目標棋串無條件死時宣告成功, so that 不必把已死的子填進碗裡才算過。
21. As a 解題者, I want 殺棋題在雙活、劫殺或活時不算成功, so that 沒殺掉不會過。
22. As a 解題者, I want 雙活題只在終局是雙活時成功, so that 單方面做成無條件活或殺死對方都不算這題的目標。
23. As a 解題者, I want 劫活題在劫活或無條件活時成功, so that 做成更強的活也算過。
24. As a 解題者, I want 劫殺題在劫殺或無條件死時成功, so that 做成更強的殺也算過。
25. As a 解題者, I want 走錯時先看到白的反駁手再看到失敗, so that 我知道為什麼無法再強迫成功。

27. As a 解題者, I want 可以停, so that 我能把「已死／已活」交給分類器。
28. As a 解題者, I want 雙方連續停後用靜態分類判定, so that 不必把死子提離盤面。
29. As a 解題者, I want 連續停後仍未定時判定失敗, so that 沒做成的題不會掛在那裡。
30. As a 解題者, I want 撲進去被提的棄子不讓做活失敗, so that 目標棋串以外的子不納入判定。
31. As a 解題者, I want 多串目標全部達成才算過, so that 只救活一串、放掉另一串不能過。
32. As a 解題者, I want 殺棋標了兩串白時必須兩串都死, so that 只屠一串不能過。
33. As a 解題者, I want 悔一對（我的手加程式的應手或反駁手）, so that 走錯可以重來。
34. As a 解題者, I want 連悔到題目開始, so that 可以從頭試另一條變化。
35. As a 解題者, I want 搜尋不設時限, so that 角題不會一直超時。
36. As a 解題者, I want 題目盤右側列出已走完的搜尋路徑（編號從 1、可捲動）, so that 我知道算過哪些變化。
37. As a 解題者, I want 思考中仍看得到盤面與新出現的搜尋路徑, so that 畫面不會假死。

## Implementation Decisions

- 產品範圍是單一個 **詰碁** 上下文；實作五個模組（ADR-0012）：**規則**、**分類**、**解題**、**題目庫**、**認圖**。Compose 只活在殼與棋盤繪製。
- **對局** 是殼呼叫的最高介面：題目 + 事件（著手、停、悔棋、重做）→ 題目盤快照（含子、狀態、搜尋路徑）+ 成功｜失敗｜等待應手。失敗時先帶 **反駁手** 再標失敗（ADR-0007）。測試與殼走同一條介面。
- **規則** 介面：題目盤上合法手、提子、自殺／倒撲、同型反覆。牆不是交叉點；真盤邊是氣較少的邊。對局與分類都經由規則，不各自重寫氣與提子。
- **分類** 介面：局面 + 目標棋串 → 終局。順序固定為 ADR-0014：提淨 → Benson → 雙活 → 贏劫／輸劫 → 雙方已停則剩餘當死 → 未定。對局測試不直接打這條介面；它是解題實作的內部 locality。
- **解題** 介面：題目 + 著手歷史 → 成功｜失敗+反駁手｜應手，並陸續報搜尋路徑。二元問題是「黑能否強迫該題型之過」（ADR-0003）。v1 實作為迭代加深 α-β／negamax，葉子呼叫分類；以後可在模組內換成 df-pn，不改介面（ADR-0015）。搜尋不設時限（ADR-0019）。開局白活點只算一次，之後先驗證白下該點；蒙地卡羅只猜著手順序，不取代精確證明（ADR-0022）。證明用相關區自底向上剪空手／必應區，靜態氣區只排序（ADR-0023）。
- **應手** 在「仍能強迫成功」的白手中取 **最長抵抗**：證明深度，再節點數，再座標檔 A→T、路 1→19（ADR-0011）。失敗時的反駁手是證明「無法再強迫」的那手白棋。
- **題目庫** 介面：題目 ↔ `.tsumego.json` 文字（kotlinx.serialization）。欄位：矩形座標範圍、四邊各為真盤邊或牆、交叉點上的黑／白子、題型、目標棋串的交叉點集合。存檔後輪次永遠黑先。不含解答樹、不含原始誰先走、不含原圖（原圖若保留，只當確認畫面的附檔，不是判定所需）。非法 JSON 或欄位不合法（例如雙活題只有一色目標）拒絕載入。
- **認圖** 介面：棋譜圖 + 黑先或白先 → 確認畫面草稿（子、建議矩形與四邊；題型與目標棋串仍由人在確認畫面補）。兩個 adapter：Desktop 自動填子；Wasm 與認圖失敗為空盤 + 原圖當底。白先在進確認畫面之前翻色。認圖不在 commonMain。
- **確認畫面** 是殼的一部分：循環改子、標目標（點一下擴整串）、切四邊、選題型、確認才交給題目庫。做活／劫活目標須為黑；殺棋／劫殺須為白；雙活題須兩色。
- TopMenu：**Input**（Black First、White First，兩邊都有）、**File**（Open、Save、Samples）、**About**。Input 走棋譜圖；File 走題目檔（ADR-0018）。
- 搜尋不設時限。每條走到終局的搜尋路徑列在題目盤右側、從 1 編號、可捲動（ADR-0019）。殼顯示實際搜尋路徑條數；列表可截取。開局算一次開局白活點；之後搜尋先驗證白下該點。蒙地卡羅只猜落點順序，精確證明仍走 α-β（ADR-0022）。證明用相關區剪空手／必應區（ADR-0023）。成功或失敗後可重做，盤面回到題目開始、搜尋路徑保留。File → Open 記住上次目錄（ADR-0021）。殼左上為「黑先殺白」這類標題、輪黑請落子／輪白思考時間。路徑搜完顯示「從路徑中思考最強應手...」。牆邊若貼著子，題目盤再空兩路（ADR-0020）。座標標號必須畫在畫布內。
- v1 棋盤：Compose Canvas 程式畫木紋、徑向漸層、高光、落影；不是真 3D 場景、不是預先畫好的棋子貼圖。
- 平台：commonMain 行為 Desktop 與 Wasm 一致。Android／iOS 不在本 spec 實作，但不要為它們預先開解題 adapter。
- 現有殼只留 About 與選單元件；去掉 K Chart／Database 殘留語意。產品名維持「詰碁」。

## Testing Decisions

- 好測試只打外部行為：給定題目與事件（或 JSON 文字、或棋譜圖+誰先走），只斷言呼叫者看得到的結果。不斷言搜尋節點數實作細節、不斷言 Benson 的內部集合、不對 Compose 截圖比像素。
- **對局**（主 seam）：幾乎所有死活行為。用小型題目盤（明確的真盤邊／牆與目標棋串）覆蓋：合法／非法手、提子、倒撲、同型反覆、做活棄子仍過、多串 AND、五種題型的過／不過、反駁手出現在失敗宣告之前、最長抵抗在並列時選較小座標、停與連續停、悔棋一對與連悔、成功／失敗後重做且搜尋路徑保留、開局白活點在後續搜尋中先被驗證、搜尋路徑字串（例如「白下 B3 -> 黑下 A3 -> 結果 成功」）出現在快照裡。同一組對局案例在 JVM 與（若 CI 允許）Wasm 上跑，應手必須相同。
- **題目庫**：往返序列化保留矩形、四邊、子、題型、目標棋串；寫出的檔再讀回來對局結果不變；缺欄位、雙活題單色目標、含白先輪次的檔拒絕。
- **認圖**：只經由固定草稿 adapter 測「黑先／白先 → 草稿 → 確認約束」。白先必須先翻色。不測影像演算法本身；Desktop CV adapter 以一張已知平面圖做可選的人工／弱斷言即可，不阻擋對局測試。
- 現有 repo **沒有**測試 prior art。新測試走 Kotlin 測試，打上述三條介面，不從 UI 點擊進入。

## Out of Scope

- 測驗模式、唯一正解、預錄解答樹。
- 定石、手筋非死活、全局勝負、讓子。
- 在牆上長出劫材或模擬盤外尋劫。
- 真 3D／可旋轉棋盤（v1 以後）。
- 實物棋盤照片。
- SGF 作為原生存檔（單向匯出若要做，另開 spec）。
- Wasm 自動 CV（commonMain 認圖）。
- 把超時當失敗或啟發式亂應手。
- KataGo／GNU Go 等第二套解題 adapter。
- Android、iOS。
- 帳號、雲端題庫、多人。

## Further Notes

- 實作順序建議：題目盤＋規則 → 題目庫 JSON → 分類（提淨／Benson／停後死；雙活與劫次之）→ 對局＋解題搜尋 → 殼（盤面繪製、選單、確認畫面）→ Desktop 認圖 adapter。
- 內建樣例至少含：角上做活（含棄子）、小殺棋、一題需要牆與真盤邊並存。不必在 v1 樣例裡塞滿五種題型，但五種都要有對局測試夾具。
- 若實作時發現分類器在「停後剩餘當死」與劫的两次假設互相搶答，以 ADR-0014 的順序為準，不要在對話裡另開例外。
